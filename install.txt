## Step 9 - The two environment variables, and the restart people forget

This is the only part of Class 4 that is genuinely automatable, and it is the part that
silently breaks the class when it is skipped.

Add these two lines to my stack's .env, next to where my other keys already live:

  BRAIN_BOT_TOKEN=<the token BotFather gave me>
  BRAIN_OWNER_ID=<my numeric chat id>

Rules for this:

  - APPEND. Never rewrite or overwrite that .env. It holds the key that decrypts my
    saved n8n credentials, and replacing it locks me out of every credential I have.
  - Check first whether either line is already there. If it is, leave it and tell me.
  - I type the token in myself. You add the line, I fill the value, or I paste it
    into the file directly. Do not echo it back to me on screen afterwards.

Then RESTART the n8n container:

  docker compose restart n8n

Explain why, because this is the trap: n8n reads environment variables when the
container starts and never again. Adding the line without restarting gives an empty
token, and Telegram answers an empty token with 404 Not Found - which reads like a
broken URL and is nothing of the kind.

Verify it actually landed, without printing the value:

  docker compose exec n8n printenv BRAIN_BOT_TOKEN | wc -c

A number bigger than 40 is right. 0 or 1 means it is empty and the restart did not
take effect.
