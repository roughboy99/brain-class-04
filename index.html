What we have been building

Business intelligence is the brain that runs a company.

Not a report. Not a dashboard. A brain — and a brain perceives, remembers, reasons, and decides.

Most small companies have the first two and rent the last two from the owner's attention. The company only thinks when the owner is awake and looking at it. That is not a data problem. It is a missing organ, and this series builds the organ, one part per week.

Class 3 · Aug 26 Ask Your Brain

Memory it can search. Your documents chunked, embedded, and answerable — with sources.

The idea, stated plainly because almost everything written about this hides it behind a product: an embedding is an array of numbers, and similarity is multiplication. A model reads a chunk of your lease and gives back 1,536 numbers. Do the same with a question and the two lists point in roughly the same direction when they are about roughly the same thing. That is eight lines of SQL.

Approach5,000 chunks
Cosine over the whole table1,027 ms
Full-text only, GIN index0.34 ms
Full-text narrows to 200, cosine ranks those45.8 ms

Twenty-two times faster, and it stays flat as your corpus grows, because the expensive half never sees more than 200 rows. That is also what production retrieval actually does: keywords plus meaning, not meaning alone. No vector database required.

What you left with
  • A kb table holding your documents, searchable by meaning
  • An /ask webhook that answers questions and cites the document
  • A dashboard with an Ask tab — plus the addendum's drag-and-drop ingest and inbox sorting
The lesson today depends on

The refusal is the feature. Ask it something your documents do not cover and it says "I don't have that in your documents" — it does not guess. A memory that says "I don't know" is worth more than one that invents. Hold onto that; today we make it say that out loud.

The lesson that runs through all three

A green checkmark is not evidence. Class 3 shipped with two bugs that both reported "status": "success" while writing wrong data — base64 stored as text, and four documents merged into one row by a unique constraint. They were caught by looking at the rows, not at the status. Today's verification does the same thing: we listen to the audio, we do not trust the file size.

The one line that matters

Class 3 is not touched. No new table, no schema change, no migration. We call your existing /ask webhook over HTTP — the same one your dashboard's Ask tab calls — and do something new with the answer.

That has a useful consequence when something breaks today: does your Ask tab still work? If yes, the fault is in this class. If no, the fault is in Class 3. One question splits every problem in half in ten seconds.

Before the hour · 10 minutes

The one command at the top walks you through all of this. If you are doing it by hand, this is the whole list — and the order matters.

1
Make a bot with @BotFather

In Telegram, search @BotFather — the blue check is on the account. Send /newbot, give it a name humans see, then a username that is unique across all of Telegram and ends in bot. Expect a couple of rejections before one is free.

That token is a password

Anyone who has it controls your bot completely. Do not paste it into a chat, a screen share, a prompt, or the class thread. In n8n it goes into a credential, so exported workflows carry the credential's name and never its value. Leaked it? Send /revoke to BotFather.

Also running Content Mate? Make a SECOND bot.

n8n prints the reason on the trigger node: "you can use just one Telegram trigger for each bot at a time." Telegram delivers each message once, to one place. Point two workflows at one bot and messages start vanishing — with no error, no failed execution, and nothing in any log.

Name the credential Brain Bot (Telegram), not Telegram account. n8n links credentials by name on import, and two with the same name will eventually attach the wrong token to the wrong workflow and look like it worked.

2
Press Start and send it a message

Open the bot you just made and press Start, then send it anything. Nothing will answer — correct, there is no workflow behind it yet. What matters is that the conversation now exists, which is what step 3 needs.

Do it from the phone you will use in class.

3
Get your chat id — now, not later

Open this in a browser with your token in place of YOUR_TOKEN:

browser
https://api.telegram.org/botYOUR_TOKEN/getUpdates

Find "chat":{"id":123456789, — that number is yours. Write it down.

The trap · do this BEFORE any workflow exists

The moment n8n's Telegram Trigger goes active it registers a webhook on your bot. While that webhook is active, getUpdates returns:

409  Conflict: can't use getUpdates method while webhook is active

That is not a broken bot and not a broken token — Telegram will not deliver messages two ways at once. Deactivate the trigger or call deleteWebhook to restore polling. You can also get your id from @userinfobot or the first n8n execution.

4
Private setup, off camera

Telegram cannot call localhost. Have a public HTTPS URL that reaches your n8n instance, keep the slide deck on the shared screen, and run this in an unshared terminal:

hidden input; values are never printed
bash setup-telegram-private.sh --stack ~/brain
Why the script is required

The Class 2 service does not inject arbitrary .env keys into n8n, and docker compose restart does not apply changed Compose configuration. The script adds an ignored private env file and an override, then recreates n8n without replacing your encryption key.

Check set/missing state and character counts without displaying either secret:

terminal
bash setup-telegram-private.sh --stack ~/brain --status
The clipboard stays private too

The script copies the token without displaying it. Paste it into the n8n credential, save, then run --clear-clipboard. If it ever appears in a recording or chat, revoke it with BotFather and replace it.

The guard — the part that can hurt you

!
Watch it refuse a stranger
0:27 – 0:33
Read this even if you skip everything else

A Telegram bot username is public and searchable. Nothing stops a stranger finding yours and messaging it. Today that bot is wired to a brain that has read your lease, your insurance policy and your invoices.

A bot that answers anyone is a bot that reads your documents to anyone.

So the first thing the workflow does with an incoming message — before transcription, before anything — is compare the sender's chat id against yours and drop everything else. That is the second node, not a hardening step to get around to later. It is why the pre-work makes you find your chat id.

Why the guard reads $env and not the trigger's own field

n8n's Telegram Trigger has a Restrict to Chat IDs field. It is a plain string — so a chat id typed there ships inside the workflow JSON the moment you export or share it. Reading $env.BRAIN_OWNER_ID in a Code node keeps the value out of the file. Use the trigger field too if you like, as a second layer, knowing that trade.

Do this yourself — today

Message the bot from a second Telegram account, or ask someone to. Watch nothing happen. Until you have seen it refuse, you do not know that it does.

Would rather not put business documents behind a public username at all? That is a completely reasonable position, and docs/UPGRADE-mic.md does the same job through your dashboard's microphone instead. It needs HTTPS and it is more work. Nobody loses the option.

P3
Voice
0:40 – 0:50

Speak the answer, convert it, send it back as a real voice note. Both traps live in this prompt.

Trap 1 · gpt-audio-mini refuses mp3

Audio output requires stream: true, and with streaming on the only accepted format is pcm16. Both failures come back as 400s with messages you only see if you read the body.

Trap 2 · concatenate the base64 BEFORE decoding it

Decoding each SSE frame separately and joining the bytes works by luck with base64 padding, and breaks the first time a frame's length is not a multiple of 3. Join the strings, then decode once.

Two questions at once collide on /tmp

Fixed temp filenames like /tmp/answer.pcm get overwritten when a second voice note arrives mid-flight. It does not error — it sends you the wrong answer. Every path carries {{ $execution.id }}, with a cleanup node after.

Verify — and don't trust the file size

from the pack folder
bash verify.sh

It prints Ready, or names exactly what is missing: libopus in the container, both env vars, the Class 3 refusal, and whether both model slugs still exist on OpenRouter.

Why it checks the model slugs

google/gemini-2.0-flash-001 returned 404 — retired during this build. A retired slug fails as a broken workflow rather than a bad name, so you go hunting in the wrong place. The preflight finds a retirement before the hour does.

The closed loop — the test that actually proves it

Forward the bot's own voice note back to the bot. It transcribes its own reply. If what comes back is the sentence it just said, the audio is real speech and not a plausibly-sized file full of static.

That is the same discipline as Class 3: a green checkmark is not evidence. Look at the rows. Listen to the audio.

When it goes wrong

What you seeWhat it means
The bot does nothing at all, no execution appears in n8nThe workflow is saved but not Active. A Telegram Trigger only registers its webhook when the workflow activates.
Everything worked, then stopped after you edited somethingYou deactivated and reactivated. Telegram is fine — check the workflow is Active again.
401 UnauthorizedTelegram read your token and rejected it. A dropped character, or it was revoked.
404 Not FoundTelegram never found the endpoint to check a token against. Usually the word bot missing in front of the token — or, in this class, an empty BRAIN_BOT_TOKEN because the container was not restarted.
409 Conflict on getUpdatesYour workflow is active and holding the webhook. Correct behaviour. Use @userinfobot for your chat id.
Messages just vanish, no error anywhereTwo n8n triggers on one bot. Make a second bot.
401 and 404 look alike and are not

Go hunting for a bad character on a 404 and you will not find one, because the token was never the problem.

Post the exact error text in the class thread — the wording is the diagnosis. Never post your token.
