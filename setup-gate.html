Class 4 · Ears and a Voice

The parts only you can do

Five steps. About ten minutes. Nothing here can be scripted — it all happens in a browser or in Telegram.

Do these in order

Step 3 stops working while the workflow webhook is active. That is not a bug; deactivate the trigger or remove the webhook to restore polling.

1
Make a bot

Open @BotFather — the official bot that makes bots. The blue check is on the account.

Open @BotFather →
  1. Send /newbot
  2. Give it a name — what humans see. Anything: My Brain
  3. Give it a username — unique across all of Telegram, and it must end in bot. Try yourname_brain_bot. Expect a couple of rejections.
  4. It replies with Use this token to access the HTTP API: and a long string. That is your token.
That token is a password

Anyone holding it controls your bot completely. Do not paste it into a chat, a screen share, a prompt, or the class thread. Leaked it? Send /revoke to BotFather and get a new one.

Already running Content Mate? Make a second bot.

One Telegram bot can carry one n8n trigger. Point two workflows at one bot and messages start vanishing — no error, no failed execution, nothing in any log.

2
Press Start, send it a message

Open the bot you just made, press Start, then send it anything — hello is fine.

Nothing will answer. That is correct: there is no workflow behind it yet. What matters is that the conversation now exists, which is what step 3 reads.

Use the right phone

Do this from the phone you will actually use in class. The chat id you are about to collect belongs to that account.

3
Get your chat id — now

Your chat id is the number Telegram uses for you. The workflow compares every incoming message against it and drops everything else.

open this in a browser
https://api.telegram.org/botYOUR_TOKEN/getUpdates
Open it →

This runs entirely in your browser. The token is not sent anywhere, not saved, and not remembered — reload the page and the box is empty. This page makes no network requests at all. Prefer not to type it here? Build the URL by hand; the shape is above.

In what comes back, find "chat":{"id":123456789,. That number is yours. Write it down.

This is the step you cannot do later

Once n8n's Telegram Trigger is active it registers a webhook on your bot, and from that moment getUpdates returns:

409  Conflict: can't use getUpdates method while webhook is active

Not a broken bot, not a broken token — Telegram will not deliver messages two ways at once.

If you already hit the 409, there is a way out that never touches your bot:

Open @userinfobot →

It replies with your numeric id and nothing else.

4
Open the n8n credential form

In n8n: Credentials → Add credential → Telegram API. Name it now; the private setup in step 5 will put the token on your clipboard without displaying it.

Name it Brain Bot (Telegram) — not Telegram account

n8n links credentials by name when you import a workflow. Two credentials called Telegram account will eventually attach the wrong token to the wrong workflow, and it will look like it worked.

Why a credential and not a node field

An exported workflow carries the credential's name and never its value. A token typed straight into a node parameter ships inside the JSON the first time you share or export it.

5
Run private setup off camera

First confirm a public HTTPS URL reaches this n8n instance; Telegram cannot call localhost. Keep this page or the slide deck on the shared screen and run:

unshared terminal; all input is hidden
bash setup-telegram-private.sh --stack ~/brain
The private file is ignored and mode 600

The script does not replace your .env or encryption key. It adds a private env file and Compose override, then recreates n8n so the values actually reach the service.

Confirm state without displaying values:

terminal, from your stack folder
bash setup-telegram-private.sh --stack ~/brain --status
A plain restart is not enough

The Class 2 Compose service did not map arbitrary .env keys, and docker compose restart does not apply changed configuration. The setup script handles both facts.

After pasting the clipboard into the n8n credential, clear it:

terminal
bash setup-telegram-private.sh --stack ~/brain --clear-clipboard

The terminal reports only set/missing state and character counts.

Go back to your terminal and paste this:

paste into Claude Code

Verify status without printing any secret, then carry on.
It should not take your word for it

Verifying a claim instead of accepting it is the same discipline as the rest of this series. If it just says "great, moving on", ask it to check.

If something goes wrong

What you seeWhat it means
"Sorry, this username is already taken"Someone has it. Try another — it must end in bot.
{"ok":true,"result":[]}You have not messaged the bot yet, or it was over 24 hours ago. Telegram only keeps updates for a day. Send it another message.
409 ConflictA webhook is active on the bot. Use @userinfobot instead.
401 UnauthorizedThe token is wrong — a dropped or extra character, or it was revoked.
404 Not FoundThe URL is wrong, not the token. Almost always the word bot missing in front: it is /bot<TOKEN>/getUpdates, all one string, no space.
The bot never answers anythingExpected, until the workflow is built in class.
401 and 404 look alike and are not

401 means Telegram read your token and rejected it. 404 means Telegram never found the endpoint to check it against. Go hunting for a bad character on a 404 and you will not find one, because the token was never the problem.

Post the exact error text in the class thread — the wording is the diagnosis. Never post the token itself.
